# SOSE v0.10.0 release closure

v0.10.0 is the first release to **complete** deprecation cycles under ADR-0011. It
removes three surfaces deprecated in 0.9.0 and extends one window that turned out
costlier to remove than its notice period justified. It adds no new runtime
capability.

## Removed (deprecated in 0.9.0)

| Surface | Migration |
|---|---|
| Importing a name from the module it was split out of by the quality-ratchet refactors (#632) | import it from the module that defines it; the 0.9 warning named it |
| `PersistentJobRunner` on persistence without job-scoped writers (#637) | implement `scoped_writer_epoch`, `claim_scoped_writer` and `transaction(writer_scope=...)`, or use SQLite/PostgreSQL; a `transaction` override must accept `writer_scope` |
| Publishing a new boundary message with a `causation_id` but no `causation_kind` (#644) | pass `causation_kind="boundary"` or `"event"`, e.g. via `CausalReference` |

Data is unaffected:
- untyped boundary messages already durable stay readable, auditable and claimable;
- the SQLite snapshot codec is unchanged (version 2);
- 0.9 databases open directly.

## Extended

- **#634, policy-less trading-company recovery**, including the SQLite path of
  `sose composition-recovery`: still supported with a deprecation warning, now
  **removed in 0.11.0** instead of 0.10.0. About 75 recovery tests exercise it
  on SQLite/memory; they move to PostgreSQL with resource policies, which changes
  their timing semantics, in dedicated PRs before the removal. ADR-0011 now allows
  a window to be extended (never shortened), with the reason recorded.
- The scoped lease for `composition/recovery_trigger.py` (#637) moves with it.

## Release gates

- CI: Python 3.12, 3.13 and 3.14, 95% branch-coverage floor, strict quality ratchet,
  PostgreSQL and chaos suites.
- `release.yml`:
  - version, tag and release-note consistency;
  - wheel and sdist build;
  - clean-install smoke;
  - upgrade from the previous minor's real wheel (`v0.9.0`).

  The upgrade gate is version-generic: it migrates unowned databases with
  `sose migrate-owners` and opens owner-qualified ones directly. It was exercised
  from both 0.8.0 and 0.9.0 before this release.

## Next milestone

- **0.11.0:** remove policy-less recovery (#634) and scope the recovery trigger's
  writer lease (#637).
- **1.0:** the readiness checklist (`docs/architecture/version-1-readiness.md`)
  remains the 1.0 gate.
