# SOSE v0.12.0 release closure

v0.12.0 completes the deprecation cycle announced in 0.11.0 (ADR-0011) and adds
the first slice of owner-qualified organization composition (P496-A).

## Added

**Owner-qualified organizational boundary routing (#496, #603).** A v2 boundary
message is bound to an admitted organization, its producer component and owner,
and its consumer component and owner, with a message id derived separately from
v1. `OrganizationBoundaryService` publishes, claims and consumes them:

- owner and ancestry checks run inside the advisory-locked boundary transaction;
- generic `BoundaryService` paths refuse a v2 publish without the facade's
  validator, never lease a v2 delivery without an organization scope, and the
  generic consumer registry will not resolve a v2 message;
- routing isolation is tested end to end on memory, SQLite and PostgreSQL.

`scoped_validator` and `organization_scope` are hooks for trusted in-process code,
not a security boundary; persistence-level authority remains #545
(`docs/architecture/organization-component-boundary-runtime-p496.md`).

## Removed (deprecated in 0.11.0)

| Surface | Migration |
|---|---|
| `ScenarioRule` (`sose.scenarios.rules`), `Engine(rules_for=...)`, `Engine.evaluate_entity` | model external interventions with `Scenario` / `ScenarioEngine`; `Engine(rules_for=...)` now raises `TypeError` |
| `sose.organizational.od2_legacy_audit` | none: tracked actors are verified by the actor time ledger |
| `od2_actor_time_ledger`, `od3_decisions`, `od3_queue_runtime`, `od3_queue_ledger`, `od4_command_lineage` | import from `actor_time_ledger`, `queue_decisions`, `queue_policy_runtime`, `queue_policy_ledger`, `work_command_lineage` |
| every name of `od2_actor` / `od4_intake` except the persisted class | import from `actor_lifecycle` / `work_intake` |

`sose.organizational.od2_actor:OrganizationalActor` and
`sose.organizational.od4_intake:ManagementWork` stay **permanently**: stored entity
records name these classes by that path. A SQLite store written by 0.11.0 (tracked
and calendared actors, OD-3 queues, OD-4 intake) was verified to reopen and
continue on this release.

## Changed

- **RNG default.** `make_random_source` defaults to `RNGMode.COUNTER`. Pass
  `mode=RNGMode.LEGACY` to reproduce streams recorded with the legacy RNG.
  `RandomSource` is unchanged. Nothing in SOSE itself called `make_random_source`
  without a mode, so no shipped domain, example or frozen evidence changes stream.
- **Boundary contract version.** `BoundaryMessage` rejects a non-integer
  `contract_version` (bool/float). No SOSE producer ever wrote one, but a store
  that contains such a row will refuse to open with "contract_version must be a
  positive integer (not bool/float)".
- CI runs PostgreSQL 19.

## Release gates

- CI on Python 3.12–3.14, 95% branch-coverage floor, strict quality ratchet,
  PostgreSQL 19 and chaos suites, benchmark smoke.
- `release.yml`: version/tag/release-note consistency, wheel and sdist build,
  clean-install smoke, and the upgrade gate from the real `v0.11.0` wheel.

## Open items

- **Composition recovery lease (#637):** the namespace-wide writer lease is still
  the default; deprecating it needs a migration for existing recovery jobs first,
  because the lease mode is part of the job's durable configuration identity.
- **#496** continues: durable execution evidence per organization/component/owner
  and derived organizational state.
- **#631** continues: migrating the example domains to the counter RNG.
