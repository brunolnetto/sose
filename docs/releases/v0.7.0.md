# SOSE v0.7.0 release closure

v0.7.0 closes the durable operational-runtime milestone.

## Durable semantic surfaces

The release provides restart-safe semantics for:

- scheduled commands and logical recovery position;
- scenario decisions and activations;
- normal resource demand, reservation, and release;
- preemptive resource demand, ownership transfer, and terminal preemption result;
- FIFO / Priority / Filter Store contents and pending operations;
- terminal Store get results;
- quantitative Container level and pending/completed operations.

## Recovery contract

Recovery follows one rule:

```text
validate complete durable state
↓
reconstruct ephemeral backend state
↓
resume execution
```

No backend-native continuation state is persisted.

Before tagging v0.7.0:

- Python 3.12 test suite passes;
- Python 3.13 test suite passes;
- Python 3.14 test suite passes;

- package metadata and `sose.__version__` both report `0.7.0`.

## Public/runtime compatibility

New domain implementations should use:

- `SimulationContext` factories for entities, commands, events, and schedules;
- `Engine` for durable runtime execution and rebuild;
- durable managers exposed by Engine for resources, stores, preemptive resources,
  and containers;
- backend-neutral contracts rather than SimPy-native objects.

The direct in-memory `context.scheduler` path is retained only for compatibility.

## Next milestone

The runtime is ready for domain vertical slices. The recommended first example is
Supply Chain / Procure-to-Pay because it exercises scheduling, Store, Container,
resource contention, supplier lead time, shortage/backorder, and causal event
chains without requiring a new runtime primitive.
