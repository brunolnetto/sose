# SOSE v0.11.0 release closure

v0.11.0 completes the one deprecation window that 0.10.0 extended (#634) and opens
the next cycle under ADR-0011: four surfaces warn now and go away in 0.12.0. It
also hardens the organizational guards and the opt-in transition authority after
independent exact-head reviews.

## Removed (deprecated in 0.9.0)

| Surface | Migration |
|---|---|
| `TradingCustomerRecoveryRunner` without `resource_policies` | pass `resource_policies` (certified intent → `ResourcePoolContract`) and `resource_organizations` (correlation → organization); recovery passes need PostgreSQL. Without policies the constructor raises `TypeError` |
| `sose composition-recovery --sqlite` | use `--postgres-dsn` and `--resource-policies` (both required now) |

A policy that maps only intents your flow never issues admits every exercised
intent exactly as before (unmapped intents keep their historical semantics), so
existing flows can move without new capacity constraints.

## Deprecated (removed in 0.12.0)

| Surface | Replacement |
|---|---|
| `ScenarioRule`, `Engine(rules_for=...)`, `Engine.evaluate_entity` | `Scenario` / `ScenarioEngine` |
| `sose.organizational.od2_legacy_audit` | none: tracked actors are verified by the actor time ledger |
| `make_random_source(...)` without `mode` | pass `mode=RNGMode.LEGACY` to keep today's streams; the default becomes `RNGMode.COUNTER` in 0.12.0 |
| OD-2/3/4 module paths (`od2_actor`, `od2_actor_time_ledger`, `od3_decisions`, `od3_queue_runtime`, `od3_queue_ledger`, `od4_intake`, `od4_command_lineage`) | `actor_lifecycle`, `actor_time_ledger`, `queue_decisions`, `queue_policy_runtime`, `queue_policy_ledger`, `work_intake`, `work_command_lineage` |

Every warning names the replacement and points at the calling code. Two persisted
class paths stay **permanently** (`sose.organizational.od2_actor:OrganizationalActor`,
`sose.organizational.od4_intake:ManagementWork`): stored records name them, so data
written before the rename keeps decoding (verified across the rename in both
directions).

## Durable data and behaviour notes

- **OD-3 queues** seeded by earlier versions have no ledger anchor. On their first
  application under 0.11 they are adopted as they stand (an anchor marked
  `adopted`), provided their applied-observation count equals the entity version;
  verification starts there. History before adoption is trusted, not verified.
- **OD-2** time tracking applies to actors enrolled with `tracked_time=True`;
  untracked actors behave as before.
- **TransitionAuthority** (opt-in): enabling it on entities with existing unsigned
  history fails closed; there is no re-anchoring or hand-over between owners.
- **Store-level limit (#545):** event ids are global per store, so another owner who
  can append events can occupy a deterministic id and block an operation. Every
  such case fails closed and writes nothing; it cannot forge accepted state.

## Release gates

- CI on Python 3.12–3.14, 95% branch-coverage floor (95.5% on main), strict quality
  ratchet, PostgreSQL and chaos suites, benchmark smoke.
- `release.yml`: version/tag/release-note consistency, wheel and sdist build,
  clean-install smoke, and the upgrade gate from the real `v0.10.0` wheel.
