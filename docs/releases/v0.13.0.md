# SOSE v0.13.0 release closure

v0.13.0 completes the job-scoped writer leases across every backend. It adds the
migration that moves a composition recovery job off the namespace-wide writer lease,
and it deprecates that lease (ADR-0011). The lease is removed in 0.14.0.

## Added

**Writer fencing on `MemoryPersistence` (#637, #665).** The memory backend now
implements the namespace-wide writer, the job-scoped writers and
`transaction(owner_epoch=, writer_scope=)` with the SQLite/PostgreSQL contract. The
scoped-writer conformance suite runs on all three backends, and `PersistentJobRunner`
works on memory. Memory leases are process-local, so the backend declares
`durable_writer_fencing = False`; recovery and OD-5a still refuse a plain memory store.

**Re-binding a recovery job to its scoped lease (#637, #666).**
`sose composition-recovery --rebind-scoped`, also available as
`sose.composition.recovery_rebind.rebind_recovery_job_to_scope`, moves an existing
recovery job from the namespace-wide lease to its job-scoped lease. The `job_id`,
`run_count` and completed-trigger history are kept. The operation:

- claims the global lease and fences any running global worker;
- refuses a job whose recorded resource-intent history names another correlation
  or organization;
- is idempotent: running it again reports `"status": "already_scoped"`.

`--scoped-writer` then runs the job under its scoped lease, which never fences other
jobs (`docs/architecture/pc6-durable-recovery-scheduling.md`).

## Deprecated (removed in 0.14.0)

| Surface | Migration |
|---|---|
| `TradingCustomerRecoveryRunner` without `scoped_writer=True` (the namespace-wide writer lease, today's default) | pass `scoped_writer=True` with one `correlation_id`; re-bind an existing job once with `rebind_recovery_job_to_scope` |
| `sose composition-recovery` without `--scoped-writer` | run `--rebind-scoped` once for an existing job, then run with `--scoped-writer` |

The runner emits a `DeprecationWarning` attributed to the caller. The command prints
the notice once on stderr. One scoped runner, or one command, handles exactly one
correlation.

**Before upgrading to 0.14, re-bind while no occurrence is in flight.** The job's
`active_trigger_id` must be empty. 0.14 cannot resume an occurrence started under
the namespace-wide lease, and the re-binding refuses an in-flight job. An idle job
can also be re-bound after the upgrade, because the re-binding stays in 0.14 (#635).

## Changed

- **Example RNG (#631, #668).** The example domains draw from the counter RNG
  (`CounterRandomSource`), keyed by logical identity. Four examples stay on the
  legacy RNG because they feed frozen evidence: manufacturing, mro, order_to_cash
  and warehouse_fulfillment. Their streams are unchanged. A database of a migrated
  example that 0.12 wrote and 0.13 resumes draws its new decisions from the counter
  stream.

## Removed

- **Incidental re-exports (#632, #667, #669).** These names had no users and a
  canonical home elsewhere:
  - the `sose.backends.simpy` request, store and resource types: use
    `sose.backends.base`;
  - simpy's own `Container`, `Store`, `FilterStore` and `PriorityStore`: import them
    from `simpy`;
  - `loads`, `MemoryPersistence` and `changes_for_dirty_records` from
    `sose.persistence.postgres`;
  - `build_storage_plan` from `sose.cli`;
  - framework classes re-exported by `sose.examples.*.simulation`, including
    `RandomSource`.

  Modules that keep re-exports now declare them in `__all__`.
