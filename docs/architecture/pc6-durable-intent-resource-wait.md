# PRD / TRD / ADR — PC6 resource-backed intent recovery and organizational clocks

**Status:** opt-in integration of the authoritative PostgreSQL temporal ledger with the bounded PC6 recovery runner. Advancing #406, **not** complete scientific promotion.

## PRD
An accepted durable boundary intent must not be dropped or declared permanently failed solely because a finite shared resource is occupied. Waiting is durable, auditable and bounded by a caller-configured retry duration. Resources must be bound to specific organizational flows through immutable correlation identity, while the same pool may be shared across organizations. Progress of organization A must not force organization B's logical position forward or make B's pending intent disappear.

## TRD
The new `IntentResourceCoordinator` receives an explicit opt-in mapping from domain intent names to `ResourcePoolContract` (for example `composition.deliver_shipment` → shared pickup courier). When an already-ACKed Command is selected by `TradingCustomerRecoveryRunner`, the coordinator checks the named authoritative pool, tries an immutable `TemporalReservation` with **reservation_id equal to the effect Command ID** and `causation_id` equal to the source immutable boundary message ID. The reservation is committed *before* the actual domain statechart operation. On success the runner executes its original handler, then releases the recorded reservation at the end of its modeled half-open logical time slot; it does not change the domain handler's own idempotent recovery contract. On crash after reservation COMMIT, retry uses the same immutable reservation and the original Command remains the source of truth. Policies are restricted to intents with immutable BusinessEffectApplied certification. If the domain certificate commits and deletes the Command but the worker dies before releasing its resource, the next runner reconstructs the certified receipt, verifies identical boundary causation and organizational binding, and idempotently releases the abandoned reservation. Absence of a Command **without** a certificate is rejected, not guessed as successful execution. An immutable `(effect_id, organization_id, resource_key, causation_id, correlation_id)` link scopes reconciliation to the runner's own effects, even when other organizations and domains reserve the same pool. An unrelated job's resource is never released merely because it shares the address.

On `ResourceCapacityError` the resource request is **not** converted into permanent business failure. A PostgreSQL table records `(effect_id, organization_id, resource_key, ready_at, attempts)`; the Command is kept. Before `ready_at`, later triggers do no new admission. The runner excludes that effect for the remainder of the current bounded pass and may execute another eligible effect. A subsequent trigger at or after `ready_at` attempts a new reservation at its own logical slot. The caller supplies both retry duration and slot duration; no wall-clock nondeterminism is introduced.

An additional per-organization PostgreSQL checkpoint stores monotonically nondecreasing logical time by an **explicit correlation → organization mapping** supplied by the runner. Two different causal correlations may map to the same organization and therefore share one monotonic resource clock; the correlation alone is not interpreted as organizational ownership. The coordinator starts later reservations at `max(request.due_at, trigger.logical_time, organization_position)` and never uses an unrelated organization's position. Physical `observed_at` remains the runner's lease clock, not the modeled resource time. The coordinator uses the owning writer epoch to fence reservation/wait/position writes across runner failover; its per-pool transactional locks remain independent.

## ADR / evidence boundary
- This API is **opt-in** and leaves the frozen Manufacturing/O2C/MRO v1 scenarios and unmapped domain intents unchanged. Registration of a pool is explicit through policy mapping; no universal process-to-resource inference is invented.
- An authoritative reservation and resource event do not automatically become one atomic transaction with the *entire* multi-transition domain statechart. The durable Command and idempotent handler reconcile a crash between admission and final state, while a single multi-commit exactly-once guarantee is not asserted.
- The modeled slot is one discrete interval. Releasing the slot is not a claim that all real calendars, setup/teardown times, skills, preemption compensation or location transfers are represented.
- The shared legacy `SimulationPosition` still exists in the underlying engine. Per-organization admission clock monotonicity is proven separately; **full per-organization SimPy/backend recovery ownership is not established here**.
- PostgreSQL resource-ledger admission and wait rows share a single authoritative connection. Postgres advisory-lock hashes may over-serialize on collisions. The engine runner still uses its existing namespace writer fencing; separate-resource concurrency is not equivalent to independent multi-writer engine ownership.

## Scientific gates
1. PostgreSQL: two accepted independent intents compete for capacity one; first completes, second becomes durably deferred, remains pending through a full connection restart and only runs at its eligible logical instant.
2. Normal and restarted executions reconstruct identical authoritative resource snapshots, causal event ledgers and independent organizational positions.
3. A wrong organizational owner cannot adopt an existing reservation; retries and completion cannot double-allocate or duplicate causal events.
4. Full Python 3.12–3.14, dedicated PostgreSQL, chaos, coverage >=95%, benchmarks and frozen historical replay. No weakening of the existing real statechart concurrent falsifier.

Policy-based admission alone is not full end-to-end equivalence.
