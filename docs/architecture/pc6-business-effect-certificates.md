# PC6 — BusinessEffectApplied receipts

**PRD** A transport ACK must not be interpreted as domain effect completion. Workers should be able to prove the business state committed, with one immutable receipt per accepted Command identity; failed certification must leave the staging Command available for idempotent recovery.

**TRD** SOSE gains a new `business_effects` authoritative keyed record collection, with `BusinessEffectApplied(effect_id, boundary_message_id, correlation_id, entity_type, entity_id, terminal_state, entity_version, completed_at)`. The receipt ID is deterministically derived from the Command ID. `BusinessEffectService.complete` checks the authoritative UoW for: a pending Command; matching, consumed boundary delivery and consumption receipt; source message/correlation; correct target; materialized terminal state; and, for O2C invoicing, a matching open Receivable. It then saves the immutable certificate and deletes the staging Command **in the same UnitOfWork transaction**. Repeated completion returns the existing certificate; conflicting immutable identity or a pending Command alongside prior certification fails closed. SQLite/PostgreSQL dirty-record adapters persist this collection as normal records, with no separate out-of-band writer.

The reference PC6 certified commands are Logistics shipment delivery, O2C invoicing, Cards Payments settlement and both customer/replenishment R2R journal postings. Other legacy commands are intentionally unchanged pending domain-specific proof definitions. `BoundaryConsumption` continues to represent transport acceptance, not certification.

**ADR** Preserve all frozen v1 message identities and contracts. Add durable proof to the **new** operational truth; do not retroactively insert certificates into historical data. Business transitions in the reference simulation commit before completion certification, then a second atomic transaction certifies terminal state and removes the staging Command. A crash between these transactions is safe **only insofar as the domain operation is itself idempotently recoverable**, which the state-driven PC6 tests check. This does **not** prove arbitrary external non-idempotent side effects occur exactly once. The source event lineage is carried by the boundary/correlation IDs and target entity version; a later PR should bind a specific domain-event ID and enforce proof for opt-in v2 causal boundaries.

**Verification** Red-first unit tests cover ACK-before-effect, wrong terminal state, conflicting correlation/command, rollback on simulated I/O failure, idempotence, immutable receipts and fresh SQLite reconstruction. Integration gates additionally test Python 3.12–3.14, PostgreSQL, chaos, 95% authoritative coverage and historical v1 replay. Issue #406 remains open for multiworker distributed causal convergence and durable order→payment→journal bindings.
